# Changelog

All notable changes to `packstub/filament-gantt` are documented in this file.

## 1.0.0 - Unreleased

First release: a Gantt chart and resource timeline for Filament 4 (4.13+) and 5.

- `Gantt` definition: `query()`, `start()`/`end()` (date or datetime casts, plain strings too), `label()`, `color()`, `progress()`, `milestone()`, `bar()` for the full shape, `groupBy()` by a column or a `BelongsTo` relation with `groups()` for a fixed, complete list (`Group::fromModels()`), `compact()` for the resource-timeline layout, `sortBy()`, `filters()`. `Bar::url()` keeps only `http(s)`, `mailto`, `tel` and relative paths: `javascript:`/`data:` values and protocol-relative hosts (`//evil.test`, `\\evil.test`) are dropped, on both sides.
- Pages and widget: `GanttResourcePage` (access follows the resource policy), `GanttPage`, `GanttWidget` (read-only by default), and the `InteractsWithGantt` trait for any Livewire component. The bars are queried and serialised by the first render that includes the chart only (a chart behind a tab gets them when it appears): a later re-render of the component (an action's modal, `$refresh`) carries no state, the browser keeps its own and reloads it renderless; a chart handed no window asks the server for its state itself.
- Axis: hour, day, week and month scales (`scales()` picks the ones offered; hour is offered first on a chart that snaps to hours, with a line at now and only the hour columns in view in the DOM) with a two-row header, today line, weekend shading, `firstDayOfWeek()`, `startDate()`/`endDate()` or a padded window around the bars (clamped by `min_window_days`/`max_window_days`), a date-range picker and select/date-range filters (native controls, styled like Filament's); zoom, window and filters kept in the URL, folded groups in local storage. Only the bars overlapping the window are loaded, with plain range predicates so the date columns' indexes stay in use; a `Filter::dateRange()` narrows its column the same way, the last day included whatever the cast, and only a real calendar date from the URL is applied.
- Moving and resizing: pointer-event drag to move (keeping the duration) or to resize either edge, snapped to `snapTo(Unit::Day|Unit::Hour)` relative to where the bar was (the time of day is kept, so datetime records move by whole days with the default unit); the browser stops a resize at `minDuration()`/`maxDuration()` rounded to whole units, so what it allows the server accepts; one pointer at a time (a second finger neither starts a drag nor ends the first); Escape or a lost pointer puts the bar back; a drag attempt on a bar that cannot move is never a click. Optimistic update, then a renderless `ganttMove`; the server re-checks `readOnly()`, `movable()`, `resizable()` (a change of both edges and the length needs both), `minDuration()`, `maxDuration()`, `lockedBefore()` and `canMove()`, saves (or runs `moveUsing()`), fires `Packstub\Gantt\Events\BarMoved`, runs `afterMove()` and answers with the authoritative bar. A refused move snaps back with a notification: a `MoveRejected`'s message (a `lockedBefore()` during the day names its time); any other exception thrown while saving (the database's, `moveUsing()`'s) is reported and answered with a generic message, never with its text. What the browser sends is read strictly: `Y-m-d H:i[:s]` or a date alone, a real calendar date in the years 1000–9999. The chart's maths is on wall-clock moments tagged UTC, so a daylight-saving change never lengthens or shortens a bar; `canMove()`, `moveUsing()`, `afterMove()` and `BarMoved` receive the same moments in the app's timezone, so `$start->isPast()` reads naturally. A record `milestone()` flags keeps its real end, shifted with the start.
- Actions: `barAction()` on click (or Enter/Space on a focused bar), `barActions()` in a menu on right-click, press-hold-and-lift (touch) or the context-menu key (Shift+F10 / Menu, where the browser has one) with arrow, Home and End navigation; each bar offers only the actions the user may run on its record (the action's `hidden()`/`visible()`/`authorize()` and Filament's default authorization, on a resource page the resource's policy, evaluated per record), within `Bar::actions()`, which the server enforces too; the create click is offered only when the create action is visible and authorized, on a group's own row as well (an empty group's first record); `createAction()` on an empty spot with the start, end and group filled in for the fields the form does not have; the group is accepted only for a row on the chart (`groups()`, a group a bar is in, or ungrouped: `canCreateIn()`, `creatableIn()` to decide yourself), never for a related record that merely exists; records resolved through the chart's query, the arguments read as strings or nothing, a listed `groups()` closure evaluated once per request. A bar's `url()` opened aside (Ctrl/⌘/Shift-click) gets a tab without `window.opener`.
- Refresh: `refreshOn([...])` Livewire events, `poll()`, and the `packstub-gantt-refresh` event.
- Hand-written `gantt.js` (one pure `layout()` function, row windowing above 200 rows, bars as `role="button"` with an accessible name, a one-day whole-day bar's tooltip reads as one date) and `gantt.css` on Filament's palette: dark mode, RTL (logical properties, zoom and hint centred either way), a vertical pan may start on a bar (`touch-action: pan-y`), no build step, no third-party Gantt library; `composer test:js` runs the browser side on plain Node (CI pins Node 22).
- Who may move: `authorizeMoves()`, by default the model policy's `update` (when the model has one) and on `GanttResourcePage` the resource's `canEdit()`; a refused record is drawn locked and `ganttMove` refuses it.
- Keyboard and touch: ←/→ move a focused bar by one unit (mirrored in RTL), Shift+←/→ its end, Alt+←/→ its start, sent once the keys rest and announced in a live region (WCAG 2.2 2.5.7); on touch a swipe scrolls the chart and a bar is picked up by holding it; dragging near the chart's edge scrolls it; a bar narrower than its handles moves wherever it is grabbed; a vertical drag is never a click, and the release of a drag abandoned with Escape never creates.
- Layout: the chart is as tall as its rows (up to the room on screen), a window narrower than the chart grows to fill its width, axis labels that do not fit are left out, a label too long for its bar is drawn after it (outside the compact layout), the today line is the panel's primary colour, focus stays clear of the sticky column and header; Today loads a window around today when the current one does not hold it; a long history opens around today; at most `max_bars` (2,000) bars per window, the toolbar saying when there are more; a range cut to `max_window_days` says so; an inverted range is swapped.
- Safe colours: `Bar::color()` and `Group::color()` (which now takes palettes and `HasColor` enums too) keep only colour shapes, the browser checks them again and sets them through Alpine's style object, so a colour from user data cannot add declarations; a colour name the panel registers (`brand`) draws as `--brand-500`.
- Server: the default window's span is read from a subquery of the two columns (a `withCount()`/`addSelect()` in the query works on MySQL and PostgreSQL, and so does a table prefix); the save, `BarMoved`, `afterMove()` and the returned bar run in one transaction on the model's connection; the returned bar is read through the chart's query; a whole-day record moves by whole days on a chart that snaps to hours; a create on an uncast DATE column prefills whole days; the group column is qualified (joins); a `groupBy()` relation is eager-loaded; a `MorphTo` group and a `maxDuration()` below the `minDuration()` are refused with an exception; an enum label reads as its label; `readOnly()` is evaluated once per request; a re-render leaves the filters' options out. One renderless call for every window, `ganttRefresh(filters, from, until, withFilters)`; `span()` takes a record; the internals the traits use are marked `@internal`; closures about a record are called with positional arguments, the others through the container.
- Translations: en, ro, ru, de, with each language's plural forms (`21 день`, `101 zile`) and date formats (`date_format`/`datetime_format` null in the config: the locale's).
- CI runs the suite on MySQL 8.4 and PostgreSQL 17 too (`DB_CONNECTION`).
