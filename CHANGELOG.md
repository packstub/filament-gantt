# Changelog

All notable changes to `packstub/filament-gantt` are documented in this file.

## 1.0.0 - Unreleased

First release: a Gantt chart and resource timeline for Filament 4 (4.13+) and 5.

- `Gantt` definition: `query()`, `start()`/`end()` (date or datetime casts, plain strings too), `label()`, `color()`, `progress()`, `milestone()`, `bar()` for the full shape, `groupBy()` by a column or a `BelongsTo` relation with `groups()` for a fixed, complete list (`Group::fromModels()`), `compact()` for the resource-timeline layout, `sortBy()`, `filters()`. `Bar::url()` keeps only `http(s)`, `mailto`, `tel` and relative paths: `javascript:`/`data:` values and protocol-relative hosts (`//evil.test`, `\\evil.test`) are dropped, on both sides.
- Pages and widget: `GanttResourcePage` (access follows the resource policy), `GanttPage`, `GanttWidget` (read-only by default), and the `InteractsWithGantt` trait for any Livewire component. The bars are queried and serialised by the first render that includes the chart only (a chart behind a tab gets them when it appears): a later re-render of the component (an action's modal, `$refresh`) carries no state, the browser keeps its own and reloads it renderless; a chart handed no window asks the server for its state itself.
- Axis: hour, day, week, month and year scales, zoomed continuously between them with Ctrl/⌘ + wheel or a pinch (half to twice a level's width, then the next level; the factor in the URL), and a Fit button that loads the span of the bars the filters leave and draws it at the chart's width with every label beside a bar still inside (`scales()` picks the ones offered; year draws months over quarters at 1.5 px a day, for roadmaps; hour is offered first on a chart that snaps to hours, with a line at now and only the hour columns in view in the DOM) with a two-row header, today line, weekend shading, `firstDayOfWeek()`, `startDate()`/`endDate()` or a padded window around the bars (clamped by `min_window_days`/`max_window_days`), a date-range picker and select/date-range filters (the toolbar is Filament's own tabs, button, input wrapper, date picker and select components); a select can be `searchable()`, with `preload()`, `getSearchResultsUsing()` (a renderless search on the server), `getOptionLabelUsing()` and `optionsLimit()`; zoom, window and filters kept in the URL, folded groups in local storage. Only the bars overlapping the window are loaded, with plain range predicates so the date columns' indexes stay in use; a `Filter::dateRange()` narrows its column the same way, the last day included whatever the cast, and only a real calendar date from the URL is applied.
- Moving and resizing: pointer-event drag to move (keeping the duration) or to resize either edge, snapped to `snapTo(Unit::Day|Unit::Hour)` relative to where the bar was (the time of day is kept, so datetime records move by whole days with the default unit); the browser stops a resize at `minDuration()`/`maxDuration()` rounded to whole units, so what it allows the server accepts; one pointer at a time (a second finger neither starts a drag nor ends the first); Escape or a lost pointer puts the bar back; a drag attempt on a bar that cannot move is never a click. Optimistic update, then a renderless `ganttMove`; the server re-checks `readOnly()`, `movable()`, `resizable()` (a change of both edges and the length needs both), `minDuration()`, `maxDuration()`, `lockedBefore()` and `canMove()`, saves (or runs `moveUsing()`), fires `Packstub\Gantt\Events\BarMoved`, runs `afterMove()` and answers with the authoritative bar. A refused move snaps back with a notification: a `MoveRejected`'s message (a `lockedBefore()` during the day names its time; a bar the lock would refuse is drawn locked: wholly before it, fixed, its end and its row too; started before it, with its end handle only (`startFixed`); a milestone on the lock itself is not past); any other exception thrown while saving (the database's, `moveUsing()`'s) is reported and answered with a generic message, never with its text. What the browser sends is read strictly: `Y-m-d H:i[:s]` or a date alone, a real calendar date in the years 1000–9999; arguments of another shape (an array for an id) are refused like any other move, never a type error in the log. The chart's maths is on wall-clock moments tagged UTC, so a daylight-saving change never lengthens or shortens a bar; `canMove()`, `moveUsing()`, `afterMove()` and `BarMoved` receive the same moments in the app's timezone, so `$start->isPast()` reads naturally. A record `milestone()` flags keeps its real end, shifted with the start.
- Actions: `barAction()` on click (or Enter/Space on a focused bar), `barActions()` in a menu on right-click, press-hold-and-lift (touch) or the context-menu key (Shift+F10 / Menu, where the browser has one) with arrow, Home and End navigation; each bar offers only the actions the user may run on its record (the action's `hidden()`/`visible()`/`authorize()` and Filament's default authorization, on a resource page the resource's policy, evaluated per record), within `Bar::actions()`, which the server enforces too; the create click is offered only when the create action is visible and authorized, on a group's own row as well (an empty group's first record); `createAction()` on an empty spot with the start, end and group filled in for the fields the form does not have; the group is accepted only for a row on the chart (`groups()`, a group a bar is in, or ungrouped: `canCreateIn()`, `creatableIn()` to decide yourself), never for a related record that merely exists; records resolved through the chart's query, the arguments read as strings or nothing, a listed `groups()` closure evaluated once per request. A bar's `url()` opened aside (Ctrl/⌘/Shift-click) gets a tab without `window.opener`.
- Refresh: `refreshOn([...])` Livewire events, `poll()`, and the `packstub-gantt-refresh` event.
- Hand-written `gantt.js` (one pure `layout()` function, row windowing above 200 rows, bars as `role="button"` with an accessible name, a one-day whole-day bar's tooltip reads as one date, a same-day shift's says the date once: `Oct 9, 2026 08:00 – 12:00`) and `gantt.css` on Filament's palette: dark mode, RTL (logical properties, zoom and hint centred either way), a vertical pan may start on a bar (`touch-action: pan-y`), no build step, no third-party Gantt library; `composer test:js` runs the browser side on plain Node (CI pins Node 22).
- Dependencies: `dependencies()` names the bars a bar waits for (a JSON/array column of keys, a relation to the predecessors, eager-loaded with the bars, or a closure returning keys or models); the browser draws a finish-to-start arrow from each predecessor's end to the successor's start (`arrows()`, pure like `layout()`), dashed in the danger colour when the successor starts before the predecessor ends, following a bar while it is dragged or carried to another row; drawn when both bars are on the chart, never enforced (`canMove()` is the place for that); `--ps-gantt-arrow`/`--ps-gantt-arrow-late`, mirrored in RTL; the row line is drawn by the label and the canvas (not the row), so the sticky labels cover an arrow routed along it.
- Moving to another row: on a grouped chart a bar dragged up or down (or carried with ↑/↓ from the keyboard) lands in the group under the pointer, the group's rows lit up and the hint naming it; `ganttMove`/`Gantt::move()` take the row's key as a last, optional argument and write the group column or the `BelongsTo` foreign key in the same transaction as the dates; only a row on the chart is a target (`groups()`, a group with a bar in the query, the ungrouped row when there is one), never a related record that merely exists; `regroupable()` and `canRegroup()` decide (default: whoever may move the bar; a change of row alone needs no `movable()`, so a bar with fixed dates can still be carried to another row; `lockedBefore()` keeps the row of a bar that ended before the lock); `canMove()`, `moveUsing()`, `afterMove()` and `BarMoved` receive the new and the previous group key after the dates (`BarMoved::isRegroup()`); each bar says whether it is `regroupable`. The chart scrolls vertically too while a bar is carried near its top or bottom edge.
- Who may move: `authorizeMoves()`, by default the model policy's `update` (when the model has one) and on `GanttResourcePage` the resource's `canEdit()`; a refused record is drawn locked and `ganttMove` refuses it; a policy without `update()` is still asked through its `before()`.
- Keyboard and touch: ←/→ move a focused bar by one unit (mirrored in RTL), Shift+←/→ its end, Alt+←/→ its start, sent once the keys rest and announced in a live region (WCAG 2.2 2.5.7), ↑/↓ unfolding a folded target group; on touch a swipe scrolls the chart and a bar is picked up by holding it; dragging near the chart's edge scrolls it; a bar narrower than its handles moves wherever it is grabbed; a vertical drag is never a click, and the release of a drag abandoned with Escape never creates.
- Layout: the chart is as tall as its rows (up to the room on screen), a window narrower than the chart grows to fill its width, axis labels that do not fit fall back to the day number, then are left out, a label too long for its bar is drawn after it (outside the compact layout), the today line is the panel's primary colour, focus stays clear of the sticky column and header; Today loads a window around today when the current one does not hold it; a long history opens around today; at most `max_bars` (2,000) bars per window, the toolbar saying when there are more; a range cut to `max_window_days` says so; an inverted range is swapped; a range the user typed is shown as typed, never widened to the chart's width; a chart whose filters arrive with its state (a render after the first) still applies the URL's filter values. A window the chart derives is at least `min_window_days` long, while a range typed in full (and the span Fit loads) is shown as asked, down to one day, so Fit fits a week of shifts; the browser says which is which, so Today or a link after a one-day range gets the minimum again. A scale picked from the tabs keeps the day in the middle of the chart (after the sticky label column), so switching back and forth does not drift; Ctrl/⌘ + wheel reaches the hour level from the day level although they are 20× apart (the step lands at the hour level's floor, and back at the day level's ceiling). A press on one spot released on another (a drag across empty canvas) creates nothing; a finger's tap may wobble as far as a touch drag's threshold, and a click with no press before it (assistive technology) always counts. A key or pointer handler keeps the chart's own `$root`, `$refs`, `$wire` and `$dispatch` after a rebuild destroyed its bar's element (↑/↓ on a compact row), so the move is sent and the focus kept. A bar is drawn clickable only when its `barAction()` is one it offers. On a phone the From/Until pickers wrap instead of overflowing the page.
- Safe colours: `Bar::color()` and `Group::color()` (which now takes palettes, `HasColor` enums and whatever `Group::fromModels()` reads from a column) keep only colour shapes, the browser checks them again and sets them through Alpine's style object, so a colour from user data cannot add declarations; a colour name the panel registers (`brand`) draws as `--brand-500`.
- Server: the default window's span is read from a subquery of the two columns (a `withCount()`/`addSelect()` in the query works on MySQL and PostgreSQL, and so does a table prefix); the save, `BarMoved`, `afterMove()` and the returned bar run in one transaction on the model's connection; the returned bar is read through the chart's query; a whole-day record moves by whole days on a chart that snaps to hours; a create on an uncast DATE column prefills whole days (sampled whatever the query selects and orders by), and so does a create on a date-only record on a chart that snaps to hours; the group column is qualified (joins); a `groupBy()` relation is eager-loaded; a `MorphTo` group and a `maxDuration()` below the `minDuration()` are refused with an exception; an enum label reads as its label; `readOnly()` is evaluated once per request, the `bar()` closure once per bar (not once more per bar action); a re-render leaves the filters' options out. One renderless call for every window, `ganttRefresh(filters, from, until, withFilters, exact)` (both flags count only as `true`); `span()` takes a record; the internals the traits use are marked `@internal`; closures about a record are called with positional arguments, the others through the container.
- Design: the chart sits in a table-style container like Filament's own tables (ring, rounded corners, shadow), with the toolbar in two groups (scale tabs, Today, Fit and From / Until at the start; the search box and the filters at the end), the chart inside it and the bar count in a footer under it; the toolbar, the filters and the bar menu are Filament's own components (tabs, buttons, input wrapper and input, date picker, select, checkbox, dropdown, badge, link), the menu in Filament's dropdown clothes (`fi-dropdown-panel`, `fi-dropdown-list-item`, an action's colour as `fi-color-*`), so the panel's theme styles everything. Kanban, Gantt and Spreadsheet share the CSS variable scheme (`--ps-gantt-bg`, `-surface`, `-border`, `-line`, `-text`, `-muted`, `-soft`, `-ring`, `-radius`, `-shadow`, `-outline`, `-mono`, the same names under each plugin's prefix); every `--ps-gantt-*` variable the docs listed keeps its meaning (`--ps-gantt-radius` is now the container's, `0.75rem`).
- Search: `searchable(['title', 'project.name'])` adds a search box to the toolbar (`like %term%` over each attribute, a dotted path through the relation with `whereHas`, the wildcards escaped with `!`, case-insensitive on PostgreSQL); the term is sent with the filters (`ganttRefresh(…, exact, search)`, `ganttSpan(filters, search)`, the last argument, nothing removed), kept in the URL (`search=`), and `getState()`/`getBars()`/`getSpan()`/`filteredQuery()` take it as a trailing parameter.
- Filters: one `Filter` class shared with Kanban and Spreadsheet. New `Filter::select()->multiple()` (`whereIn` by default, a list to `query()`), `Filter::boolean()` (a Yes / No select, a bool to `query()`), `Filter::toggle()` (a checkbox, `query()` required and told on the first render, gets `true`); the searchable family and `dateRange` as before. `state()`/`emptyState()` give the browser the URL's value in the filter's shape (`''` / `[]` / `false` / `{from, until}`), `toArray()` carries `multiple`. Renderless `ganttFilterOptionLabels(name, values)` beside `ganttFilterOptions` and `ganttFilterOptionLabel`; the browser has `isActive()`, `pickSelect()`, `pickFilter()`, `toggleFilter()`, `resetFilters()` and `activeFilterCount()` under the same names in all three plugins. A multiple select is in the URL as repeated `f.<name>` parameters, a toggle as `f.<name>=1`.
- `filtersLayout()` on `Gantt` (`FiltersLayout::Dropdown`, the default: behind a funnel button with the count of active filters and a Reset link; `Toolbar`: inline after the search box; `AboveContent`: a row of their own under the toolbar), `getFiltersLayout()`, and `filters_layout` in `config/filament-gantt.php` as the default (`dropdown`, `toolbar` or `above`; another value throws). A chart without filters shows no funnel.
- Strings `search`, `filters`, `reset_filters`, `clear`, `yes`, `no` in en, ro, ru, de.
- Translations: en, ro, ru, de, with each language's plural forms (`21 день`, `101 zile`) and date formats (`date_format`/`datetime_format` null in the config: the locale's).
- CI runs the suite on MySQL 8.4 and PostgreSQL 17 too (`DB_CONNECTION`).
